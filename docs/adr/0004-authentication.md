# 0004-authentication

JWT を利用した 認証構成を採用

## 適用範囲

本プロジェクトの認証・認可機能に適用する

## 背景

ユーザーごとの投稿・コメント・画像データを保護するため、認証・認可機能が必要

- 投稿機能
- コメント機能
- ユーザー登録
- 写真アップロード

## 選択肢

### Session認証

- サーバー側でセッション管理を行う
- 一般的な認証方式
- 実装がシンプル
- セッション無効化が容易
- サーバー側で状態管理が必要

### JWT認証

- トークンベース認証
- APIリクエスト時に認証情報を送信
- API中心設計に適している
- Token管理が必要
- Tokenの漏洩時のリスク
- Logout制御が煩雑

### Supabase Auth

- 認証基盤を外部サービスに委譲
- 実装コストを削減できる
- OAuth連携を容易に実装できる
- 認証内部構成の学習が限定される
- 外部サービス依存が強くなる

## 決定

JWT を利用した 認証構成を採用

## 理由

- APIベースの認証を実践的に学習したい
- セキュリティ設計を実践したい
- Frontend / Backend 分離構成と相性が良い

## トレードオフ

- Token管理が必要
- セキュリティ設計を適切に行う必要がある
