# 0001-Zustand

Zustand（ズースタント）採用

## 適用範囲

本プロジェクトのフロントエンドにおけるグローバル状態管理に適用する

## 背景

グローバルの状態管理が必要

### 必要な理由

- アプリが扱う状態が増えると、「どの状態がどこで管理されているのか」がわかりにくくなり、複雑化する
- その結果、開発や保守が難しくなる
- 親コンポーネントから子コンポーネントへ状態を渡す際に「バケツリレー」のようなコードが増え、全体の可読性が低下する
- 状態の変更による不要な再レンダリングが発生し、アプリの動作が遅くなる

## 選択肢

- Context API
  - Propsのバケツリレーをすることなく「state」と「stateを変更するメソッド」をアプリケーション全体で使えるようにするための、ReactのAPI
  - React標準の状態共有手段
  - 追加ライブラリ不要
  - ただし、再レンダリング制御が難しく、大規模化すると管理が煩雑になりやすい
- Redux Toolkit
  - 状態管理のデファクトスタンダード（業界の標準）
  - 厳密な設計・状態遷移管理が可能
  - ただし、学習コストやボイラープレート（必要な機能を実現するために繰り返し書く必要がある、手続き的または冗長なコード）が多い
- Zustand
  - 軽量な状態管理ライブラリ
  - Hookベースでシンプルに記述できる
  - Provider不要で導入が容易

## 決定

Zustandを採用

## 理由

- 学習コストが低い（Reactに慣れている場合）
- 軽量でシンプル
