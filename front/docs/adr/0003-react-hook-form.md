# 0003-react-hook-form

React-Hook-Form 採用

## 適用範囲

本プロジェクトのフロントエンドにおけるフォーム機能設計に適用する

## 背景

拡張性・可読性を高めるため、機能ごとの整理が必要

### 必要な理由

- useState ベースのフォーム管理では、入力ごとにuseStateやonChangeハンドラが必要になる
- フォーム管理が増えるとコード量が増加し、可読性が低下する
- バリデーションやエラー表示の管理が複雑になりやすい
- 入力ごとのstate更新により、不要な再レンダリングが発生しやすい

## 選択肢

- useStateでの管理
  - 管理する値をuseStateに定義
  - onChangeハンドラを定義
  - フォーム項目が増えると定義も増やす必要がある（エラー表示やバリデーションも）
  - 他のロジックのstateもあり、コードが読みづらい
  - 入力のたびにstate更新→再レンダリング

- React-Hook-Form
  - フォームの項目ごとにuseStateを書かなくてもよい（onChangeも）
  - 項目が増えても管理が破綻しにくい
  - シンプル
  - 非制御ベース（値をDOM側で保持し、必要な時にref属性で参照）なので、不要な再レンダリングを抑えやすい

## 決定

React-Hook-Form を採用

## 理由

- コードをシンプルにでき、可読性が高い
- 不要なレンダリングを抑えられる
- フォームの送信イベントでhandleSubmit関数を使用することで、送信前に自動でバリデーションが実行される

## トレードオフ

- 項目の少ないフォームの場合はuseState管理の方がシンプル
